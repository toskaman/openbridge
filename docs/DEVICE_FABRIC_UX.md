# Device Fabric UX and guided steps

Guided dialogs are generated by src/fabric/guidance.py: deterministic, vendor-aware (Xiaomi/Redmi/POCO, Samsung, Oppo/Realme/OnePlus/vivo, Huawei/Honor, Google, Sony, Motorola, generic) and Android-version-aware (Android 12+ "Nearby devices" vs Location on 11 and older), with TV variants (Device Preferences paths, remote-friendly). Each dialog shows: goal, why it is needed, what OpenBridge already tried automatically, the minimal owner action, and how the wait resolves (event or bounded retry). No model generates these steps.

Issues covered: usb_debugging_off, usb_authorization_pending, companion_install_blocked, companion_not_running, bluetooth_off, ble_permission, owner_scan_disabled, wifi_adb_pairing, freebox_pending. Install errors from adb are classified (e.g. INSTALL_FAILED_USER_RESTRICTED -> companion_install_blocked) and OpenBridge retries every 15 s for 10 minutes while the guide is shown.

Real case that motivated it: on the participant's Xiaomi, `adb install` failed with INSTALL_FAILED_USER_RESTRICTED until MIUI "Install via USB" was enabled; the Xiaomi guide now names exactly that switch.
Tests: tests/fabric/test_guidance.py; UI: tests/e2e/fabric_smoke.py, guided_smoke.py.
