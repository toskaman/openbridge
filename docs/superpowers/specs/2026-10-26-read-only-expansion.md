# Read-only expansion

The participant authorized ongoing development, Meta-assisted visual redesign, and read-only discovery of owned devices. Keep the simulator intact; add opt-in USB discovery through the installed adb executable without adb connect or subnet scanning.

Use opaque process-local handles rather than serial numbers in browser responses. Device states are device, offline and unauthorized; only device permits inspection. Query a fixed read-only command allowlist for Android version, manufacturer, model, SDK, battery and free storage. Never interpolate model output into commands. All subprocesses have timeouts, bounded returned data and sanitized failures.

The default inventory remains the simulator for deterministic offline demonstration. An explicit source=android query selects USB inventory. An Android inspection must revalidate current authorization and never fall back to a simulated report. UI changes must be informed by an actual Meta model response and record exact model, prompt hash, returned identity, token use and estimated cost on GitHub.

Cloud model calls remain disabled in unattended application runtime pending a reliable free-credit check. A manually supervised design call may use a freshly observed positive promotional balance with a tiny reserved allowance. Reservations remain consumed on ambiguous timeouts. No automatic retries or paid fallback.

Tests: absent adb, mixed states, two devices, redacted identifiers, untrusted argument values, fixed commands, timeout, malformed output and model/budget refusal. Browser simulation flow stays functional and real-device mode shows honest waiting states.
