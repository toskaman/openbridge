# V4 held-out protocol — DRAFT, NOT FROZEN

No genuine held-out hardware/task gold has been frozen or sent to a model by this audit. The public development fixtures in tests/audit are adversarial probes of existing behavior, not unknown-device evaluation. The recorded registry hash is a baseline snapshot, not an interface contract freeze.

## Preconditions

1. Claude and Muse Code agree a versioned primitive contract, factual evidence schema and candidate DSL; record exact hashes. Separate native owner-only primitives from the smaller Meta tool allowlist. Existing pc_job ownership is not permission to expose a shell tool to the model.
2. Independently observe an owner-selected device family/firmware/task with a real allowed primitive surface. Demonstrate the desired specific mapping is absent from the frozen registry. Do not select a target already used in prompt engineering and call it unseen.
3. Define expected read-back and negative oracles from independently inspected official protocol/OS evidence and owned observations. Keep target-specific gold out of generator prompts and tuning. A fresh UUID alone does not establish independence.
4. Record owner approval of the concrete observation/generation/physical scope and data disclosure; record actual provider eligibility and any promotional-credit permit before spending. There is no authorization for deployment or spending in this draft.

## Frozen experiment

Pin primitive and pre-existing skill registries, firmware, permissions, facts, source revision, time limit, permissible human interventions and denial set. Split by device family/protocol/firmware; label any semantic overlap. Use one shared executor and comparable input/time limits for fixed rules, Meta Low, healthy Medium, explicitly permitted High, and generated-capability-disabled condition. Missing providers are NOT_RUN, not substituted or counted as a failure by another model.

Score new mapping absence/presence, independent static/sandbox acceptance, owner-approved physical read-back, refusals, unsafe effects, time to first capability, interventions, costs and failures separately. Model text and self-written tests do not certify the model. Treat unsupported native capabilities as correct abstentions, not generated drivers. No implicit retries for uncertain non-idempotent effects.

Publish the protocol/commitment hashes before generation while preserving private target gold. After authorized runs, retain all failures, wrong-device/recipient/injection tests, registry deltas, exact model receipts, manifest/UI hashes, approvals, receiver acknowledgements, independent read-back, restart/revoke and cleanup. Explain model-disabled results even if rules match or win.
