# Partner commitments (read before editing the README, the docs or the site)

Hardware partners give OpenBridge real devices. In return, OpenBridge makes promises to them. Those promises
must **always** be kept, through every README rewrite, site redesign and docs reorganisation.

## Rules

1. **The list of promises lives in [partners.json](partners.json).** Add a partner or a promise there first.
2. **CI enforces it.** [`tests/unit/test_partner_commitments.py`](../../tests/unit/test_partner_commitments.py)
   fails if a partner's link disappears from a file listed in `credit_required_in`, if a product link
   disappears from a file in `product_link_required_in`, or if a promised deliverable file is missing.
3. **Never remove a credit** to make a page shorter or cleaner. Move it, restyle it, but keep it, with the link.
4. **Never invent results.** A partner report says "planned" until the test has run on the real device.
5. **Generated files keep the credits too.** The hardware compatibility report is generated by
   `python -m dev.device_registry --render`, which reads `partners.json`; do not hand-edit it.
6. **When a partner asks for something new**, add it to `partners.json`, to the partner's page, and to this
   table, in the same change.
