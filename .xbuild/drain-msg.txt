feat(server+companion): drain companion orders to the PC (typed+voice)

The Companion queued owner-typed and owner-spoken commands on-device but no
server code ever read the queue: every order sat on Got-it forever. This
wires the missing half:

- src/runtime/command_drain.py: background poll (5 s) of get_commands on
  every command_submit relay; text goes to the local low-tier NL parser,
  voice clips download over the signed one-shot URL (size+sha verified) and
  transcribe via local Meta MMS STT; every command gets exactly one signed
  report_command (outcome / clarification / honest error), each in a worker
  thread so a slow parse never stalls polling; local tiers only, outcomes
  reported never auto-executed.
- src/cli.py + src/server.py: start the drain in both production mains.
- Companion: caption resets to idle when the 25 s answer window expires.
- 9 unit tests with real crypto both ways (tests/runtime/test_command_drain).
- Registry row 31 (physical e2e 9/9) + report/audit updates.

Proven live on the physical phone: typed FR order parsed by Llama 3.2 3B and
reported to the caption; 6 voice clips fetched (sha match), transcribed by
local MMS, parsed and reported aloud (TTS). A zombie pre-drain test server
that poisoned earlier runs (double-bind on 18795) was killed; scripts now
refuse a busy port.
